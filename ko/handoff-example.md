# AI 작업이 끊길 때 다음 세션에 무엇을 넘겨야 할까요?

다음 세션이 읽을 목표, 범위, 확인한 진행 상황과 다음 행동이 필요합니다.
Autopilot의 공개 평가에는 실제로 만든 작업 기록이 있습니다. 그 기록 덕분에
복구가 더 좋아졌다는 효과까지 입증한 것은 아닙니다. 이 글은 저장소의 평가
산출물을 설명하며 개인 체험담이나 현행 릴리스를 새로 실행한 결과가 아닙니다.

## 맡긴 일과 남긴 기록

[10월 22일 코드 평가](https://github.com/PresentJay/autopilot-skills/blob/main/evals/results/2026-10-22/code-autopilot/input.json)에서는
할인율을 100으로 제한하되 더 낮은 할인율의 동작과 사용자 메모를 보존하도록
요청했습니다. 당시 평가한 스킬은 preview 버전 `f4a6d33`입니다. 현행 v2는
기록이 필요한 작업에만 지속 기록을 사용합니다.

[실제 일지](https://github.com/PresentJay/autopilot-skills/blob/main/evals/results/2026-10-22/code-autopilot/journal.md)에는
처음 실패한 테스트, 수정 내용, 결과 검사, 비대상 입력의 보존 여부가 기록돼
있습니다. [실제 상태 파일](https://github.com/PresentJay/autopilot-skills/blob/main/evals/results/2026-10-22/code-autopilot/state.json)은
완료 조건과 검증 방법, 대상 버전, 일지 위치를 연결합니다. 다음 세션이 읽을 수
있는 파일이 남았습니다.

| 다음 실행에 필요한 정보 | 공개 기록에 담긴 내용 |
| --- | --- |
| 목표와 범위 | 할인율 상한, 기존 계산 보존, 보호할 입력 |
| 확인한 실패와 수정 | 실패한 테스트와 `discount.py`의 상한 처리 |
| 검사 방법과 대상 버전 | 기록한 검사 명령, 완료 조건, 버전 식별 정보 |
| 남은 작업 | 기록한 완료 상태. 이 사례는 한 작업을 마친 시점의 기록 |

평가를 진행한 에이전트는 수정한 코드와 원본 입력도 별도로 검사했습니다.
그럴듯한 상태 파일만으로 기록 내용이 사실임을 증명할 수는 없습니다.
[전체 조건과 한계](../evidence.html)를 함께 확인하세요.

## 일시정지된 미션은 그대로 보존했습니다

[10월 29일 후속 평가](https://github.com/PresentJay/autopilot-skills/blob/main/evals/results/2026-10-29/summary.json)에서는
재개를 허용하지 않은 채 일시정지된 미션을 점검했습니다. 기존 코드와 기록이
바이트 단위로 보존됐습니다. 이는 일시정지를 존중한 결과이며 재개 성공 시험은
아닙니다. 지속 기록 경로를 명시적으로 확인하려던 두 실행은 완료 턴 없이 시간
한도에 도달해, 바꾼 기록 요청 처리를 실제 실행으로 검증하지 못했습니다.

두 평가 모두 재설명 횟수, 인계 후 빠뜨린 요구사항, 장시간 복구의 안정성을
측정하지 않았습니다. 짧은 작업은 기본 goal을 쓴 비교군도 모두 통과했습니다.
품질·속도·비용의 일반적인 우위는 입증하지 않았습니다.

## 내 작업에서 써보기

[중단된 작업을 이어가는 안내](when-agent-stops.html)에 설치 방법과 지속 기록,
상태 확인, 명시적 재개 프롬프트를 정리했습니다. 다음 세션에 넘길 필요가 있을 때
기록을 요청하세요. 짧은 작업은 자동으로 기록 파일을 만들지 않습니다.
스킬이 앱의 중단을 막거나 종료한 앱을 다시 실행하지는 않습니다.

다음으로 확인할 질문은 구체적입니다. 새 세션에 이 기록을 주면 같은 설명을
반복하는 횟수나 빠뜨리는 요구사항이 줄어들까요?
[새 세션 비교 과제](https://github.com/PresentJay/autopilot-skills/issues/18)에서
이를 확인하려 합니다.
