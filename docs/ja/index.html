01 / MISSION

Autopilot を使う理由

標準の goal でも作業を継続できます。Autopilot はミッションと作業記録をまとめ、指示の再利用、進捗の確認、中断した作業の再開を助けます。

01

再利用できる指示

目標、許可された範囲、完了条件をまとめます。

02

チェックポイントごとの根拠

何をどの版で確認したか、何が不明かを記録します。

03

作業を残して再開

既存の編集と途中の成果物を確認してから続行します。

02 / IN PRACTICE

コードにも、調査にも、文書にも。

普段のエージェントとツールを使い、合意した範囲内で進めます。

$autopilot 公開 API を変えずに import の失敗を修正して。再現して統合テストで確認し、既存の編集を残して。標準 goal モードで完了まで続行して。
$autopilot 提供した仕様書のレイテンシとオフライン対応を比較して。出典を示し、不明な情報は不明のまま報告して。
$autopilot source.txt を非技術者向けの概要にして。数値と制約を確認し、既存のメモを残して。

今回の実行で完了できる作業はスキル本体だけを読み、成果を確認します。状態・ログファイルや作業フォルダー全体のハッシュ一覧は作りません。永続記録は次のセッションへの引き継ぎ、定期監視、明示的な記録依頼、既存ミッションに使います。既存の一時停止状態とユーザーの編集は常に保護します。

03 / EVIDENCE

約束より先に、根拠を。

標準 goal と成果物・実行コストを比較します。短い例だけでは長時間の信頼性や時間短縮は証明できません。

標準 goal に対する優位性は未確認

小規模比較の条件、結果、限界を確認してください。
